# Local SimBrief MCP usage

Scope (updated November 12, 2026): this page covers the **local stdio tool server** (`ifdispatcher`), which prepares SimBrief requests, retrieves existing plans into immutable local snapshots and estimates takeoff N1. It does not generate plans. Plan generation, the dispatcher agent and the remote MCP server are documented in the [agent guide](agent-usage.md) and [deployment guide](deployment.md); BUILD-04 live acceptance passes on the current release ([evidence](../evidence/live-acceptance.json)). Automatic import into Infinite Flight is not implemented.

## Install and start

From the project directory:

```bash
uv sync --locked
SIMBRIEF_ALIAS=YOUR_ALIAS IFD_DATA_DIR="$PWD/data" uv run --locked ifdispatcher
```

The server uses stdio and awaits an MCP client; it is not an interactive shell. No password or generation API key is required for retrieval. The `data` directory contains private raw OFPs in SQLite; it is Git-ignored. Use an absolute data directory when connecting a client. Restrict local access and preserve this directory for restart recovery.

Generic local MCP client configuration (replace paths and Alias):

```json
{
  "mcpServers": {
    "infiniteFlightDispatcher": {
      "command": "/ABSOLUTE/PROJECT/.venv/bin/ifdispatcher",
      "env": {
        "SIMBRIEF_ALIAS": "YOUR_ALIAS",
        "IFD_DATA_DIR": "/ABSOLUTE/PROJECT/data"
      }
    }
  }
}
```

No global client configuration was modified. A real SDK stdio client has been tested; ChatGPT, Claude, and Codex application-specific acceptance remains pending. ChatGPT remote access requires a separately selected hosting/authentication path.

## Tools

`simbrief_capabilities` reports implemented operations and the generation blocker.

`prepare_simbrief_dispatch` accepts a `request` object. At minimum include trip, leg, and positive revision. Missing flight inputs are returned for clarification. Complete requests require origin/destination ICAO, aircraft ICAO or custom-airframe identity, timezone-aware departure, and KGS/LBS units. Passengers, route, and runway are optional. Unknown fields are rejected. The current input surface is deliberately explicit; support for remaining provider dispatch options is unfinished BUILD-04 work.

```json
{
  "request": {
    "trip": "ExampleTrip",
    "leg": "Outbound",
    "revision": 1,
    "origin": "KIAD",
    "destination": "KEWR",
    "aircraft": "A20N",
    "departure": "2026-10-31T14:00:00Z",
    "units": "KGS",
    "passengers": 120
  }
}
```

This saves the agreed request locally; it does not generate a flight.

`retrieve_simbrief_plan` accepts trip, leg, revision, and `user_requested: true`, with optional documented `static_id`. It makes one provider request and saves the response only if route, aircraft, units, and an explicitly requested runway agree. It rejects custom-airframe snapshots until exact mapping can be verified. It does not prove full input correlation: departure time, payload, route, and generation identity are not yet validated against a submitted operation. Do not describe imported OFPs as generated by this application.

`read_simbrief_snapshot` reads a saved trip/leg/revision without network access. Takeoff selection uses runway identity. The result preserves all runway analysis, including missing targets. Raw bytes and the full response remain privately stored; tool results expose a selected structured view.

`estimate_takeoff_n1` accepts trip, leg, revision, optional `engine_override` (when the Infinite Flight livery's engine differs from SimBrief's) and optional `full_thrust_n1` (N1 read in Infinite Flight at full throttle on the runway). It reads the saved snapshot's selected takeoff runway and returns a **labeled simulation-grade estimate**: N1 as a ratio of full-thrust N1 with an uncertainty range, an absolute target when calibrated, a briefing line, method, assumptions and sources. Scope: A20N/A21N TOGA/FLEX, and B38M (LEAP-1B28) TO/TO-1/TO-2 with optional `D-` assumed temperature; pressure altitude −2,000 to 2,000 ft. The 737 MAX path assumes TO-1 ≈ 10% and TO-2 ≈ 20% fixed derates and an unpublished 30 °C ± 5 flat rating. Other aircraft, derates and conditions return explicit `unsupported_*` or `missing_input` states. LEAP-1A26 also reports the FlyByWire model's absolute N1. Method and source limits: [thrust source inventory](../research/thrust-source-inventory.md); implementation: `src/ifdispatcher/thrust.py`.

## Recovery and limits

- Changed request or OFP bytes require a new revision. Existing snapshots are never overwritten. Even an identical plan fetched again may have different provider metadata and require a new revision.
- A missing-input result creates no complete request. Prepare again with the missing fields.
- Network/provider errors leave saved snapshots intact. Explicitly retry retrieval only when requested; there is no polling loop.
- This stdio server exposes no generation tool. Browser generation, its waiting and uncertain-outcome handling belong to the dispatcher agent ([agent guide](agent-usage.md#bounded-browser-management)).
- Thrust output is an estimate only: displayed N1, not proof of equal real or simulator thrust. A provider-reported target would remain unverified.

## Verification

```bash
uv run --locked pytest -q
bash scripts/check-dead-code.sh
uv run --locked python scripts/validate.py
```

The validator executes local tests, lint and pinned Vulture, and writes a timestamped source digest, check output and result under `artifacts/validation/`. Its overall outcome also requires the database-derived live acceptance record ([`live-acceptance.json`](../evidence/live-acceptance.json)) to match the source being validated. The Product validation workflow runs it in CI on every pull request; see [CONTRIBUTING.md](../../CONTRIBUTING.md). MCP SDK 1.27.0 is pinned; all resolved runtime and development dependencies are locked in `uv.lock`.
